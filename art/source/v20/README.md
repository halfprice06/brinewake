# V20: the lock is seen to turn

A Claude agent authored this pass on 2026-09-22, after reading the
`aseprite-pixel-art` skill and every one of its references in full. It is
scripted pixel art: the in-between frames are generated by
`tools/art_v20/gate_switch.py` from the v13 gate's own clusters and put into
an editable Aseprite document by `tools/art_v20/gate_switch.lua`, run in a
headless Aseprite built from source. None of it is mouse drawing, and no
image-generation tool or external bitmap contributed a pixel.

## What changed and why

In the eighth self-play trial the lock switch was instant: the gate sprite
jumped from one resting drawing to the other, and both seats missed that the
tide had turned. The switch now plays for two seconds, the same length as
the lane's flood and drain fronts:

- the semaphore arm lifts off the old side, passes upright, and lands on the
  new side before the water moves (cause, then effect);
- the handwheel turns a turn and a quarter, the pale pointer spoke ending
  where the new side's rest drawing has it;
- the shaft that was dry fills and the other drains: floats ease out, move
  fastest mid-stroke, overshoot one pixel and settle.

Only the "working parts" layer changes; every other layer is the v13 drawing.
The last frame of each direction is pixel-identical to the rest drawing it
hands over to.

## Document

`gate_switch.aseprite`, 160x144, 24 frames at 166 ms (the engine's 5 ticks),
tags `to_south_dry` and `to_north_dry`. Keys `gate_to_{side}_dry_{0..11}`,
anchor (80, 128) like every gate key, packed in a band under the v19
rectangles (y 7832).

## Build

    python3 tools/art_v20/gate_switch.py wp_north.png wp_south.png <parts>
    aseprite --batch --script-param root=$PWD --script-param parts=<parts> \
      --script tools/art_v20/gate_switch.lua

`wp_*.png` are the "working parts" layers of
`art/source/v13/gate_{north,south}_dry.aseprite`. The Lua script checks that
each frame lands in order before it exports.
